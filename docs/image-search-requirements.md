# 需求记录:自建以图搜图(商品图库)

## 1. 背景与目标
- 在自己的商品图库里做**以图搜图**:上传一张图,返回库内最相似或同款的商品。
- 目标是**成本尽量低**。阿里云图像搜索最低档约 ¥980/月(包月,按容量和 QPS 计费),对小规模使用偏贵,因此不采用。

## 2. 数据规模
- 商品图约 **1 万到 2 万张**,以后可能增长。
- 商品类型:**包包、手表、鞋子、衣服**。这几类细节多、款式容易混淆(同款不同颜色、同品牌相近款)。

## 3. 运行环境
- 服务器:**2 核 4G**,没有 GPU。
- 估算内存够用(单模型约 2GB 以内,双模型约 2 到 3GB),但不宜同时跑其他大程序。

## 4. 技术方案(初步)
- **自建**,不使用付费图搜服务。
- 用开源模型把图转成向量,比对相似度排序。
- **模型倾向:** DINOv2(ViT-B)加 CLIP 或 SigLIP(ViT-B)组合。DINOv2 擅长找"同款",CLIP 擅长风格相近,也便于以后扩展文字搜图。搜索时合并两者的相似度,权重根据测试调整。
- **存储:** 1 到 2 万张规模(向量文件约几十到一百多 MB),直接用文件(如 `.npy`)或 SQLite 即可,暂不需要向量数据库。库存增长到几十万张后,再考虑 pgvector 或 Qdrant。
- **入库:** 一次性批量处理。服务器 CPU 较慢,建议先在本地电脑转好向量再上传到服务器。
- **搜索:** 服务器只负责查询,单次约 1 秒以内,可处理小规模并发。

## 5. 准确率提升措施(可选)
- 图片尽量干净(白底或简单背景),手表等细节商品使用高清图。
- 每个商品入库多张图(正面、侧面、细节),查询时取最高分。
- 先按品类过滤再搜索。
- 结果作为"前 5 名候选"供人工确认,不做全自动判定。

## 6. 验收方式
- 准备 **30 到 50 张**实际会用到的测试图,统计正确商品出现在**前 1 名和前 5 名**的比例,并重点测试易混淆情况(同款不同颜色、实拍图对官方图)。

## 7. 待确认事项
- 图片存放方式:本地文件夹,还是 URL 列表?
- 文件名或数据里是否有商品 ID、品类等信息?
- 搜索结果需要返回什么:仅图片文件名,还是商品 ID、价格等?
- 使用场景:自己人工使用,还是做成网页或接口给多人调用?
- 服务器上是否还运行其他服务(影响可用内存)?
- 该服务器所在地区(日本或其他)。

## 8. 风险与限制
- 没有任何模型能保证 100% 准确。
- 同款不同尺寸的商品外观几乎相同,图搜难区分,需要靠商品信息补充。
- 模型效果还没有在实际商品图上验证,需要先做小规模测试再确定最终方案。
